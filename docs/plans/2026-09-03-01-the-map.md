# 01 — The map

## Intent

The owner opens one page and sees everything on Hello Revenue's plate, ranked, in the columns he already thinks in; drags a card to change its priority or its stage; opens a card and reads what it is for without reading code. The page is true to the project's written record — its plans and suggestions — and to nothing else, because in this slice nothing runs yet.

This slice is the surface. It has to be good enough that the owner prefers it to 0.1 for reading and planning on day one, with no runtime behind it. If it is not, the sequence stops here and this plan is amended.

### 1. A project is a corpus of plans

Needle knows a project as a path to a repository that keeps plans in `docs/plans/` (live) and `docs/plans/done/` (archived), and suggestions in `docs/slice-suggestions/` with the same split. A card is born from a document; a document is the card's substance. The board stores what the document cannot: column, position, rulings, and the rows a session or the owner writes on the card.

**The corpus is the only way in (owner ruling 2026-09-03).** A plan or suggestion written by any session, anywhere, becomes a card the moment the file lands in the project's plans or suggestions folder; a plan into Planned, a suggestion into Backlog. Needle watches the corpus and never writes a plan. A card keeps its number when its document is renamed or archived, so identity follows the document, not the path.

Done means: Hello Revenue is registered as the first project by its path; every live plan and suggestion in it is a card, and a file added while the board is running is a card within seconds, without a click; a card opens to the document's title, its intent section, its effort gate and its status line, rendered from the file; when a document moves to `done/` the card knows. The 0.1 card file (`docs/board/needle-board.json` in the Hello Revenue repo) is imported once — column, position, and rows — so the owner's existing ranking is the starting state, and nothing in Needle writes to that file.

### 2. The grammar of the columns

The columns are the owner's, from 0.1: Backlog (written ideas), Planned (written plans waiting their turn), Up next (what we should do next, owner-ranked), Executing, Decision moment, Executed, Done, Not now. In this slice every move is the owner's, because nothing runs. The grammar that later slices will enforce by machine is written here as the column definitions the page shows.

Done means: the eight columns render with their definitions one hover away; a card's column and position are the board's state, persisted the moment they change, and survive a restart; a document with no card and a card with no document are both visible as such, never silently dropped.

### 3. The kanban is a real kanban

Drag and drop between and within columns, with the drop position obvious before release; keyboard reordering; sorting within a column by the owner's rank, by age, by gate; a card that shows at a glance its number, title, gate, and one line of essence, and expands in place to its intent, its core points, and its rows; every action a card offers reachable from the card without leaving the board. On a laptop screen and on a wide one.

Done means: the owner ranks a column by drag alone, without a menu; a dropped card lands where the preview said; expanding a card never scrolls the board away from it; the frontend holds one design system in `frontend/src/components/ui/` and every card, column and chip is built from it — a ratchet refuses a raw colour or a bespoke primitive outside it.

### 4. The board is true and durable

Every move is persisted before the page says it happened, and the page never shows a state the store does not hold. State lives in the board's own store, outside any project's working tree — 0.1 kept it inside the project repo and lost it twice to a reset of that tree.

Done means: a move survives a backend restart and a page reload; a write that fails is shown as failed on the page, never as success; the store carries an audit row per change (what moved, from where, to where, when, by whom — the owner or a session), and the page can show a card's history from it.

### 5. Built to be maintained by sessions with no memory

Done means: backend layered as what things are (`domain/`), what happens (`board/`, pure over typed inputs), durable execution and storage (`infrastructure/`), thin API (`api/`); frontend types mirror backend Pydantic types one module per concept; ratchets from the first commit for the boundaries in `CLAUDE.md` (no `subprocess` under `board/`, no deferral markers, no raw colours, no `any`); a `README` a session can run the project from in three commands.

## What this slice does not do

Nothing runs. No Start, no sessions, no windows, no model rule, no machine moves, no alarms. Those are slices 02 and 03 and their absence is the point: the surface is judged on its own.

## Terrain

- **0.1's grammar and its incidents:** the Hello Revenue repository, `docs/board/README.md` — the intent section at the top is this project's intent; the mechanics below it are what 0.1 did, with the incident behind each. Read for the column rulings, the card shape (`t`, `deep`, `b` rows, `gate`, `ch`), and the "three origins of a card" rule. `docs/board/needle-board.json` there is the import source for item 1.
- **0.1's tests as scenarios:** `tests/scripts/test_needle_board*.py` in that repository. For this slice the relevant families are the store (locking, idempotent row writes, gate as a field never a row), the alarms about documents without cards and cards without documents, and the page behaviours. Read them as "what a board can get wrong", not as code to port.
- **The plan document shape** the parser must read: a `#` title, a `**Status:**` line, an `**Effort gate:** <level> — <why>` line, an `## Intent` section. Suggestions share the title and a `**Found by:**` line. Both exist by the hundred in Hello Revenue; parse what is there, never demand a new format of the corpus.
- **Stack decisions, made:** Python via `uv`, FastAPI, Pydantic v2, SQLAlchemy + Alembic on SQLite for the store; React + TypeScript + Vite + Tailwind for the page; `@dnd-kit` for drag and drop (accessible, keyboard-capable, no jQuery-era baggage). Versions are the executing session's call and live in the manifests.
- **Design:** the owner judges UI in product terms. Before building the page, a signed comp: one static HTML mock of the board and one of an expanded card, shown to him, iterated, then built. 0.1 was built from a comp; the comp is where its column grammar was settled, and that step is why the surface held while the runtime did not.
