## Intent

When the tests run, their scratch files land in the laptop's memory, so the board sees less free memory than the machine really has and refuses new work, or the machine kills work that was running, for room a directory is holding. After this card, a test run of Needle's suite puts its scratch space on disk whatever the machine's temp folder is, a check refuses a run that lays it in memory, and the same setting for every other project's tests on this laptop is a card on the machine's board with this card's evidence, so Hello Revenue's suites follow without Needle's code knowing about them.

What does not change: the board's 5 GB floor is the owner's number and still reads the machine's own memory figure, which was right all along — the floors really were taking that memory; the harness's own scratch under the temp folder and the browser's are not this card's; the board never stops a running suite.

## Rulings

1. **System wide means the laptop's environment, and that is the machine's card.** The owner's reading is right: the fix has to hold for every test run on this laptop, not one project's. But "through Needle" does not mean inside the board's code. Rejected: the runtime setting the temp root on every session it launches — the runs that ate memory on the 9th included suites run by hand in terminals and suites run as transient services by sessions, and a variable set on a launched session reaches neither the terminal nor a service the user manager starts; it would also put one test tool's knob in the board's runtime. Rejected: Needle's suite alone — Hello Revenue's suite lays scratch the same way (eighteen of its test files use pytest's temp path, read 2026-09-10) and is most of what runs here. So the laptop-wide setting is filed as a defect on the machine's board, where the user environment already lives (`~/.config/environment.d/`, tracked in the record's `home/.config/environment.d/`, which the user manager imports for terminals, sessions and transient services alike), and this plan does not write it.
2. **Needle's suite keeps its own default and its own check even once the laptop's setting lands.** The suite runs on the rented machine before its record is applied, and in any public clone on a machine whose temp folder is memory, as this laptop's is; a default that depends on the machine being set up is a wish, and the check is what makes the failure loud (HOW-WE-WORK §5). The two are not two ways to do one thing: one is this suite's own root, the other the laptop's default for everything else.
3. **The floors keep pytest's own numbering and pruning; only the root moves.** Rejected: a bare `--basetemp` per run — pytest wipes a given directory and uses it bare, with no numbering, no pruning, and a collision when two lanes name the same one, which is how three lanes' suites ran on the 9th.
4. **The check reads what the root stands on, never where it is.** A root under `~/.cache` is today's answer; the intent is "not in memory", so the refusal reads the filesystem type of the mount the resolved root is on and refuses a memory-backed one, which lets a machine whose temp folder is a disk pass and refuses a `--basetemp` given by hand into memory.
