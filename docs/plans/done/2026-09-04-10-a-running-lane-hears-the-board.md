# 10 — A running lane hears the board

**Found by:** the owner, from the board's Idea door on 2026-09-04 (conversation 8c853ff9)

Neither lane's plan named the other's file, so Start was honestly clear; both drifted while running. #109 said what it was doing there on the watercooler within sixteen minutes of its start. #174, started forty-five minutes before #109 existed, has run an hour beside it without a word — not because it chose silence, but because nothing told it: a lane hears its neighbours in its brief at Start and in `needle fold` at the end, and nothing in between. **Effort gate:** high — the mechanics are small, but the hook runs inside every session's every tool call on this machine and must stay non-blocking under a down or slow board; the ratchet that held "the hook writes nothing to stdout" was written at the altitude of its method and has to be rewritten at the altitude of its intent, not deleted; and the heard-mark is written by the server while the loop reads, which is one lock and one write, decided in the Rulings.
**Sequencing:** none. Independent of 08 in intent; the pill will name 08's lane while it is live because both plans name `api/app.py` and `infrastructure/store.py`, which is the pill telling the truth.

## Intent

A lane that is running hears what the board learns about it while it runs — that it has drifted into another lane's file, and what the other lanes have said on the watercooler since it last listened — inside its own context, within a minute, once. Today the brief and the fold are the only two moments a lane is told anything, and a collision that begins after Start is seen by the owner on the pill and by no one in the lane. Slice 07 made a collision "refused, seen, or written down — never silent"; this slice makes it *heard* by the lane that can act on it, without the owner carrying the word by hand.

### 1. The board keeps a word for each live lane and says it once
Done means: for every lane with hands on its worktree the board holds what it has not yet told that lane — the collision sentence when the drift verdict for the lane changes (appears, names different files, or clears), every watercooler line said since the lane last heard by another lane or by the board (never the lane's own), and the "#M folded over this lane's edits" line when a fold lands over it — as one typed `Word` (Pydantic, mirrored in the frontend) with one sentence per fact in the board's voice ("#174's lane is also editing domains/campaign/types.py, infrastructure/asset_update_coordinator.py. Say in the watercooler what you are doing there."); a read of the word moves the lane's heard-mark in the store so the next read is empty; the mark survives a restart of the board; the open card shows when its lane last heard and what, beside the watercooler's last line it already shows, so the owner can see a lane was told. A test on the two-lane fixture: A drifts into B's file, A's word names B's edits once and is empty on the second read; B's watercooler line reaches A's word once and never B's own; the mark is where it was after the store is reopened.

### 2. The hook carries the word into the session on every tool use, cheaply, and never blocks
Done means: the hook is registered for PostToolUse as well as the four events it has; on that event it asks the board for the word of the lane at its working directory with a half-second timeout and prints the answer as that event's context for the model — `{"hookSpecificOutput": {"hookEventName": "PostToolUse", "additionalContext": "…"}}` on stdout with exit 0, which Claude Code inserts beside the tool result as a system reminder (hooks reference, "Add context for Claude"; checked 2026-09-04 against the reference itself after a summary of it said PostToolUse had no such field — it does) — and prints nothing when the word is empty, the board is down or slow, the directory is no lane, or the payload is a subagent's; the PostToolUse event is never queued or posted — it is a read, and the queue stays the events' path; the board's answer never reads git or reconciles: it reads the loop's last read of the lane (the same staleness the pill has, at most the loop's beat) and the store, and writes the heard-mark, under the loop's lock; `needle hook install` adds the event to a project's settings idempotently, and the close-out runs it on every project on the board; the brief's neighbour rule tells the lane it will be told when it collides and when others speak, so it need not poll `needle watercooler`. The cost is measured before and after on a lane's own tool calls and written in the close-out; the prediction, fixed now: under 80 ms per tool call including the interpreter, and half a second at worst when the board is down or hung — the script's own timeout is the ceiling, because Claude Code's default for a command hook is 600 s and would let a hung board hold every tool call. A test runs the real script with a PostToolUse payload against the small HTTP server that stands in for the board: it prints the word; it prints nothing on a 503, on a server that answers after the timeout, on an unknown directory, and on a payload carrying `agent_id`.

### 3. The hook ratchet holds the intent, not the method
Done means: `tests/ratchets/test_one_rule_one_hook.py` no longer asserts that `print(` is absent from the script; it asserts what that line was for — the hook's own failures never reach the session — by refusing any write to stdout outside the one function that answers PostToolUse from the board's own answer, and by holding that function's every path through the same catch-all; the standard-library-only and never-raises rules stay as they are; PostToolUse joins the events the ratchet requires registered in this repository's own settings; the test proves it sees what it looks for with a script that prints from `main`.

## Loop
We think a word in the session within a minute of drift will change whether the *second* lane into a file speaks on the watercooler before the fold, because a lane that is told acts and a lane that would have to poll does not (#109 spoke unprompted because its brief named #174; #174 never heard of #109). Signal: on the next three collisions on any board, whether both lanes have a watercooler line before either folds. If they do, keep. If a told lane stays silent, the word is landing but not acted on — change the wording to a question the lane must answer, not the channel.

## Rulings
Recorded as the build makes them, each with the alternative rejected.

1. **Tell, do not refuse.** Rejected: a PreToolUse deny on an edit into a file another lane is editing. The rebase at the fold is where two lanes in one file resolve, #109's edit in the coordinator is legitimate ground its plan does not name, and a refusal would put the owner in the loop on every legitimate overlap. The signal that would reopen this: a fold that lands over another lane's edits whose re-verify finds a break.
2. **PostToolUse, not Stop.** Stop fires at the end of a turn, which for an autonomous lane is the end of its work — the moment the fold already covers. Rejected also: a timer that writes into the session's terminal (the board never is the thing that runs, and a windowless lane has no terminal).
3. **Once, by a heard-mark in the store, not by memory in the hook.** The hook has no state and stays a standard-library script; the mark lives where the watercooler lives and survives a restart.
4. **The word reads the loop's last read, never git.** A PostToolUse fires many times a minute; the drift on the pill is already at most a beat stale, and the word is the same fact at the same staleness.

5. **The mark moves whenever hearing moved, not only when the word says something.** A lane told nothing still records the baseline it started from, and a lane whose own lines went by records passing them; only a word that said something stamps `at` and `text`, which is what the card shows. Rejected: writing the mark only on a word that said something, which is what item 1 reads as — it leaves a quiet lane with no mark at all, so every one of its thousands of tool calls recomputes the baseline from the project's whole watercooler. The cheapness is the feature here, not a detail of it.
6. **The lane's hearing is the lane's, not its session's.** The baseline is the lane record's `first_seen`. Rejected: `lane.hands_on_since`, which follows the winning session — and a resume forks the session id (verified live in slice 04), so a resumed lane would re-hear every line said before the resume, which is exactly the noise the "once" is for.
7. **The word path imports `http.client`, not `urllib.request`.** Importing `urllib.request` cost about 15 ms of a ~40 ms interpreter start, on every tool call of every session on this machine; `drain` keeps it, imported where it is used. Rejected: one import list at the top, which is how every other script here is written — the altitude of that convention is "a script reads top to bottom", and it loses to a measured cost on the hottest path on the machine.
8. **The word takes a lock of its own, not the loops' lock.** The read of the mark, the compose and the write are one act, so two hooks from one session's parallel tool calls cannot both carry the same word. Rejected: the loops' lock, which every door and every read of the machine takes — it is held through a reconcile's git reads over every worktree, and a word queued behind one would blow the hook's half second and be dropped *while the server still moved the mark*, which is the one way a word is lost for good.
9. **The ratchet holds "the hook's own failures never reach the session", not "no `print(`".** Nothing writes to stdout outside the one function that answers PostToolUse from the board's own answer, and that function's every path is inside one catch-all. The test proves it sees what it looks for: a copy of the script that prints from `main`, and one that writes at module level, are both refused. The plan asked for the rewrite and it is the whole of item 3 — the old line was the method, this is what the method was for.

## Close-out

- **The prediction is met; the number was the wrong shape, and reading it at the wrong moment nearly reported a regression that does not exist.** Fixed in the plan: "under 80 ms per tool call including the interpreter". Measured with the real script, old and new **interleaved run for run**, because taken as separate rounds the same unchanged script gave 47.7 ms and 114.3 ms medians an hour apart. At load 5–10 (three lanes and a served board): old 114.3 ms median, new 155.1 ms board up, 113.6 ms board down — which reads as "the word costs 40 ms and the ceiling is missed". At load ~4, the same pair, twice: old 59.5 / 51.4 ms, new 61.9 / 51.6 ms. **The word costs 0.2–2.4 ms of the median, not 40; the 40 was the machine's load.** With the board down the new script is *faster* than the old (41.9 vs 50.6 ms), because the word path no longer imports `urllib.request` at module level — that one import was 40.3 ms against 24.7 ms for the rest, and removing it paid for the word twice over. The worst case — the property the plan called the real one — holds: a hung board never held a call past the script's own half second. The lesson is the shape, not the number: an absolute per-call ceiling measures the machine, so the WATCH row names the **delta on an otherwise quiet machine**.
- **The word costs one indexed read and at most one small write per tool call**, after findings 1 and 2: the watercooler is read with `after=<the mark>`, so a lane that has heard everything reads no rows at all, and the mark is written only when hearing moved.
- **What the served board needs after the fold:** the main checkout's `frontend/dist` rebuilt and `needle-serve.service` restarted (migration 0008, a new route, a page change), then `needle hook install` on every project on the board so each gets the PostToolUse entry. Recorded on the card as it was done.
- **Proof of search before the new primitives.** Reused: `WatercoolerLine` and `Store.say`/`watercooler` for what is said, the loop's `LaneSnapshot` for `edits` and `colliding` (ruling 4: never git), `Collision.sentence` verbatim as the board's own words, `project_of_cwd` and `card_of_cwd` for the attribution the posted events already use, `Store.forget_lane` for clearing a relaunched card's hearing, the `Heard` primitive and `ago` on the page, `hook_install`'s idempotent loop for the new event.
