# 02 — The runtime

**Status:** DONE — built 2026-09-04, reviewed in `docs/reviews/2026-09-04-the-runtime.md`. On the build session's branch, awaiting the coordinating session's fold to `origin/develop`.
**Written:** 2026-09-04, the morning after slice 01 landed, from `docs/INTENT.md` lesson 1 and the runtime half of Needle 0.1 as read on 2026-09-03 (nine fixes in one day, all here).
**Effort gate:** xhigh — this is the half of 0.1 that failed, and it failed on facts that no type carries: one session registry per subscription, a browser opener that strips its environment, a launcher whose child is the terminal, a daemon that forks a session on resume. The hard part is knowing what is true on this machine before building on it; every item below names the fact and how it was verified, and the executing session re-verifies each before relying on it.
**Sequencing:** after 01. Slice 03 (the doors and the loops) is the board's use of what this slice provides; nothing in 03 starts until the runtime's four jobs are proven from the command line.

## Intent

The board reads what runs. It never is the thing that runs. This slice builds the thing that runs as its own service with four jobs, each usable from the command line and from the owner's own terminals before the board ever calls it:

1. Know every session on this machine as one list, whatever subscription it runs under.
2. Say where work runs next: the strongest model on any subscription that still has it, the next model only when the top one is exhausted everywhere.
3. Start a session where the rule says, in its own worktree and its own process scope, so nothing the board does can end it.
4. Open a window into any session, prove it opened, and let the owner close it without ending the session.

When this slice is done, 0.1's launcher, rescue, window code and ladder are all replaceable by calls to this service, and the owner's own terminal gets the same model rule as a lane.

### 1. One list of sessions

Claude Code keeps a session registry per config directory (verified 2026-09-03: `claude agents --json` under one subscription cannot see sessions started under another). 0.1 polled only the registries its ledger remembered, and forgot one on the owner's answer, so a live lane rendered as a stopped copy of itself. The same session id also appears in several registries after a cross-subscription resume, and only one copy has a process.

Done means: the runtime lists every session across every declared subscription slot as one typed list, each row carrying its slot, its short id, its session id, its working directory, its state and whether a process exists (`/proc`, never the registry's word alone); when one session id appears in several registries, the row with a live process wins and the stale copies are named as such; a session with no process is never reported as working. The list is what the owner's terminal, the board and every other caller read.

### 2. One model rule — and it lives in `claude-acct`, not here (amended 2026-09-04 09:40)

The owner's ruling (2026-09-03): use Fable 5.1 whenever we can; only when Fable 5.1 is exhausted on all my subscriptions do we switch to Opus. 0.1 encoded this correctly in one function and wrongly in a second one that the page rendered. On the morning of 2026-09-04 a parallel session landed the rule at machine level, where the owner's own terminals get it too: `claude-acct best --from <slot> --tried a,b` prints the slot (and `--model opus` when no slot has Fable), refusing a slot whose signed-in identity is not the one it should hold; a `StopFailure` hook with matcher `rate_limit` in every slot's settings runs `claude-acct handoff` the moment any turn dies on a limit, hands a supervised terminal session off to the chosen slot, and for an unsupervised background session writes `~/.cache/omarchy/claude-acct/handoff/bg/<session_id>.json` and stops. That is the one rule and the one detector on this machine.

Done means: the runtime asks `claude-acct best` and never re-implements the rule or parses a limit message; every caller in Needle (Start, the preview on the card, a move) gets its slot and model from that one call; a test proves the runtime's answer equals `claude-acct best`'s for the same inputs by calling the real command against a fixture cache. The `needle claude` wrapper named in the first draft is withdrawn: `claude-acct use/auto` already is that wrapper for terminals.

### 3. A session starts where the rule says, and nothing the board does can end it

0.1 spawned lanes from its own process, so they landed in its service cgroup and died with every restart. It resumed sessions to move them, which forks the session id and, when the daemon still held the original, produced two copies of one conversation in one worktree (verified twice on 2026-09-03; `claude stop` first is what prevents it). A resume also loads the whole transcript, and a 10 MB transcript stuck on "loading conversations" for good.

Done means: a start runs `claude --bg` in a transient scope of its own (`systemd-run --user --scope`, one unit per session, named after the card), under the slot `claude-acct best` names, with the prompt-settling flags a windowless session needs; a start is verified by positive evidence (a registered row that stays alive through a short window, a `StopFailure` read as death with its reason) and never by the launcher's exit code; **a move is the runtime acting on the handoff file the hook writes for a background session** — stop the session where it ran, resume it on the slot the file names (or start a fresh session with the brief when the transcript is above a size the executing session measures), record the new slot, and say so on the card; the runtime never detects a limit itself. The handoff file carries what a move needs (session id, slot, model, and, agreed with `claude-acct`, the worktree path and short id); the runtime records the slot each session runs on in its own store, and clearing a session's rescue history never clears its slot.

### 4. A window into any session, closable without ending it

0.1 opened a window by running the launcher through a 30-second wait and killing the child when the wait expired; the child was the terminal. It also offered a "resume in a terminal" door on cards whose session was live elsewhere, which forked the conversation into a window the owner could not close without ending it.

Done means: a window is opened detached (no pipe, no wait, its own session) and proved by one more window under its app-id than before, within a deadline, or fails loudly by name; a window into a live session is always `claude attach`, so closing it ends only the viewer; a session live nowhere gets a fresh session in its worktree with the transcript as context, and the window's first line says so; app-ids follow the `org.omarchy.<kind>-<card>` contract so the compositor's rules place them, and every board window is a tab in one group on the owner's terminal workspace (the rule landed 2026-09-03); the runtime never opens a second window for a session that has one, and never reopens one the owner closed.

## What this slice does not do

It does not decide which windows should exist, when a lane is rescued, or what a card says about any of it. Those are the board's decisions and belong to slice 03. This slice provides the four jobs as a service and a command line and proves each one by hand.

## Terrain

- **0.1's runtime, as the record of what goes wrong.** In the Hello Revenue repository, `scripts/needle_board_server.py`: `_start_session` and `_next_rung` (the ladder, correct), `_work_model` (the second chooser, wrong), `_resume_lane` (the stop-then-resume and the ledger clear), `_open_terminal`, `_window_count`, `_ensure_lane_windows` and the window ledger, `_refuse_open_lane`; `scripts/needle_board_live.py::read_agents` and the lane merge; `scripts/needle_board_runout.py` (per-slot run-out knowledge, the lane ledger); `scripts/needle_board_accounts.py` (slots, cached allowances, `env_for`). Read as scenarios, with `tests/scripts/test_needle_board*.py` beside them. Nothing is ported.
- **The machine's facts, each verified 2026-09-03:** registries at `~/.claude/jobs/<short>/state.json` and `~/.claude-accounts/<slot>/jobs/`; daemons under `/tmp/cc-daemon-<uid>/<daemon>/pty/<short>.sock`; `claude attach` adds no registry row and exits when the session ends; the browser opener spawned by a login carries none of the session's variables, so `~/.local/bin/chromium-router` reads them from the process tree; a session's transcript lives under `<config dir>/projects/<cwd slug>/<session id>.jsonl` and a cross-slot resume copies it.
- **Subscriptions:** `~/.claude-accounts/accounts.json` (slot → Chromium profile → expected identity), `claude-acct` (login, cache, identity), the statusline's identity check in `~/.claude/statusline/statusline.py`.
- **The compositor:** Hyprland with a Lua config; `hyprctl clients -j` proves windows; `hyprctl eval` runs Lua at runtime; the board-terminal rule and group in `~/.config/hypr/hyprland.lua`; `omarchy-launch-tui --app-id=… <cmd>` opens a terminal whose process chain ends in `foot` itself.
- **Shape:** `runtime/` beside `board/`, reached through a typed interface the board imports and a `needle` subcommand family (`needle sessions`, `needle where`, `needle start`, `needle window`); the ratchet from slice 01 that refuses processes under `board/` stays the boundary.

## Acceptance criteria (behaviours)

1. `needle sessions` lists sessions from at least two slots as one list, with the live copy of a duplicated session id winning and the stale copy marked.
2. `needle where --from <slot>` returns the slot and model the ruling implies, given the cached allowances; with Fable spent on the starting slot and headroom elsewhere it answers Fable on the other slot; with Fable spent everywhere it answers Opus on the starting slot; a slot with the wrong identity is skipped and named.
3. `needle start <repo> <card> "<brief>"` starts a session in its own scope under the chosen slot, and `systemctl --user` shows the scope; stopping the runtime service leaves the session running.
4. A move to another slot leaves exactly one live copy of the session and records its slot; the record survives a runtime restart.
5. `needle window <short>` opens a tab on the terminal workspace, proven by window count, still open after two minutes; closing it leaves the session working; a second call opens nothing and says why.
6. No test opens a real window or touches a real subscription: the fixture floor from 0.1 (launcher made unfindable, slot root redirected) is rebuilt as ratchets here.
7. By hand at the close: the owner starts one session through `needle start`, watches it through `needle window`, closes the window, and confirms the session still working; the result goes in the plan's close-out.

## Rulings

1. **The model rule and the wall detector live in `claude-acct`; Needle only asks and acts** (coordinating session, 2026-09-04 09:40, on the split proposed by session work-3f). Rejected: a second rule inside the runtime, however faithful — two rules gave two answers in 0.1 and would again the day one changed.
2. **Registries stay per slot; the one list is built by reading each slot.** Rejected: symlinking every slot's `jobs/` into one directory, which would erase the fact that a session belongs to a subscription and break the identity check.

The rest are the build session's, recorded as they were made (Claude, 2026-09-04, verified on this machine):

3. **The runtime is one package with one door to the machine.** Every path it reads and every command it runs lives in `runtime/machine.py`; every other module asks that door. Two ratchets hold it — only `machine.py` may import `subprocess`/`shutil` or spawn, and only `machine.py` may name a home path, read the environment or resolve a command. Rejected: each module reaching the OS where it needs to (0.1's shape), which made the fixture floor impossible to build cleanly and left every test one missed mock away from the real machine.

4. **A row is live only when its process is in `/proc` with the start time the registry stamped; the registry's word is kept but never believed.** The same session id in several registries is one session, and the copy with a live process wins; the others are marked stale, never dropped. Verified 2026-09-04: `sessions/<pid>.json` carries `pid` and `procStart` (field 22 of `/proc/<pid>/stat`), present on every live row and gone from a stopped one; a cross-slot resume leaves the old slot's copy as it was. Rejected: trusting `claude agents --json`'s state (0.1 rendered live lanes as paused when the JSON was polluted, and a dead record read as working — the trap the `/proc` check exists to close).

5. **A start walks the ladder by acting on the wall detector's handoff file, never by reading the death.** A launch that registers `blocked` and grows a handoff for its session id (newer than the launch) is stopped where it ran and resumed on the slot the file names. Verified 2026-09-04: a `--bg` launch on a spent slot registers `working` at 0.5 s and `blocked` at 1.0 s with the process alive and idle until stopped. Rejected: the runtime classifying the limit message itself (the split; and a substring match on a session's own prose was 0.1's trap).

6. **A launch is verified by `/proc`, the registry and the handoff over a five-second observation window, never by the exit code; a handoff older than the launch is the move it is acting on, not a new death.** Rejected: trusting `claude --bg`'s exit 0 (it exits 0 over a session that dies 1.6 s later — the two dead lanes 0.1 reported as launched).

7. **A session's processes are adopted into a transient scope after a verified start, and the adoption is confirmed by polling `/proc` until the cgroup settles.** `StartTransientUnit` returns a queued job, so the move lands a moment after `busctl` returns — verified 2026-09-04: the scope read empty at once and held the process under a second later, and reporting that success as unverified was bad information the poll removes. Rejected: `systemd-run --scope` at launch (the daemon owns the fork, so the session is never the runtime's direct child; adoption after the fact is the only lever); trusting the `busctl` success without the `/proc` confirm.

8. **Each slot's daemon is adopted into `claude-daemon-<slot>.scope` and each session into `needle-<card>.scope`.** Verified 2026-09-04: every daemon and every lane on this machine sits in 0.1's `needle-board.service` cgroup, kept alive across its restarts only by that unit's `KillMode=process`. Rejected: leaving them there — the runtime owning the scope is what makes "nothing the board does can end it" true without depending on 0.1's unit surviving.

9. **A move above eight megabytes of transcript starts a fresh session with the brief instead of resuming.** Verified 2026-09-04: a print-mode loader read 14.6 MB in 1.9 s, but an interactive resume of a 15 MB transcript never registered a process in 120 s — 0.1's "loading conversations" hang, which a lane and a look window both need an interactive session to avoid. The number is a belief with a loud loop: every resume is verified, so a hang reads as unconfirmed, never as alive. Rejected: always resuming (the hang); a print-mode preload (fast, but the surface that opens the transcript is interactive).

10. **A window is opened detached and proved by one more client under its app-id; the runtime records the window, notices the owner's close on the next read, and never closes one or reopens a closed one.** Verified 2026-09-04: `omarchy-launch-tui` ends in `exec setsid`, so its exit code cannot fail and the terminal is a grandchild; the proof is the compositor's client list. Rejected: waiting on the launcher (0.1 held a pipe and killed the terminal when the wait expired); an in-memory window ledger (0.1 reopened windows the owner had closed after a restart).

11. **A look window forks the session (`--resume --fork-session`), so closing it cannot end a session that is live elsewhere; above the size limit it names the transcript rather than loading it.** Rejected: `--resume` without the fork (0.1 forked one conversation into a window the owner could not close without ending it, and ran two copies in one worktree).

12. **The runtime's own records live in three tables with no foreign key to the board's** — where a session runs, its rescues, its windows — so clearing a session's rescue history never clears its slot. Rejected: one table (a clear would lose the slot, the exact loss lesson 1 warns of).

13. **The fixture floor stands in for the machine whole: paths through the variables `machine.py` reads, commands through stand-ins first on `PATH`, under an autouse fixture on every test.** Rejected: mocking `subprocess` per test — a missed mock touches the real machine, which is the one thing criterion 6 forbids, and the two door ratchets plus the floor make the miss impossible rather than merely unlikely.

## Close-out

Built 2026-09-04 by the build session (Claude, Fable at xhigh). Review: `docs/reviews/2026-09-04-the-runtime.md`. Each acceptance behaviour, stanced before the fold, with the evidence — the five command-line jobs were run against the real machine with a throwaway store, starting and stopping one real session at a time and closing every window after.

1. **`needle sessions` is one list across slots** — met. The live run listed sessions from armana and gmail in one list: this build's own live session, the owner's Hello Revenue lanes, three interactive terminals read from their process records, and every ended lane, each row carrying its slot, short id, state, working directory and scope. The live copy of a duplicated session id wins and the stale copy is marked (`tests/runtime/test_registry.py`); a row is live only with its process in `/proc`, so a session with no process is never reported as working.
2. **`needle where` returns the rule's answer** — met. `needle where` answered `fable on armana`; `needle where --from armana --tried armana:fable` answered `fable on hrme`; both equalled `claude-acct best --json` for the same inputs, run beside them. The runtime parses only `{slot, model, why, config_dir}` and never a limit message (`tests/runtime/test_rule.py`). A slot the rule skips for a wrong identity is the rule's to skip; the runtime shows its words.
3. **`needle start` runs in its own scope, and nothing the runtime does can end it** — met. A live start landed a session on armana verified after five seconds, and `systemctl --user` showed `needle-card-live-2.scope` holding it; the `needle` process that started it had already exited, so the session runs in its own transient scope, not under any runtime process. The scope adoption is confirmed by polling `/proc` (ruling 7). The walk down the ladder on a wall, the fresh-vs-resume split and the dead-launch verdicts are on the floor (`tests/runtime/test_launch.py`).
4. **A move leaves exactly one live copy and records its slot** — met on the floor, not live. `tests/runtime/test_launch.py` starts a real session on the floor, files a handoff, moves it, and asserts one live copy on the target slot with the other marked stale, the slot recorded, the rescue logged, the handoff removed, and the slot record surviving a new store and a rescue clear. Not run against the real machine: a live move needs a real limit wall, which did not occur during the build, and staging one would spend a second real session and its quota for no evidence the floor does not already give.
5. **`needle window` opens a tab, closable without ending the session** — met. A live window opened `org.omarchy.lane-card-live-1` on workspace 3 (the board-terminal group, by the owner's Hyprland rule), proved by the compositor's client count; a second call was refused by name; closing it through the compositor left the session working; a read recorded the close; an explicit call after the close opened a new one. The look door for a session live nowhere and the size-limit naming are on the floor (`tests/runtime/test_windows.py`).
6. **No test opens a real window or touches a real subscription** — met. The fixture floor (`tests/floor.py`, `tests/fakes/bin/`) redirects every path `runtime/machine.py` reads and stands in for every command it runs, under an autouse fixture on every test. Two ratchets hold it: `tests/ratchets/test_the_board_never_runs.py` (only `machine.py` spawns) and `tests/ratchets/test_the_runtime_stands_on_the_floor.py` (only `machine.py` reaches the machine, and at test time every path is under the floor and every command is a stand-in).
7. **The owner's end-to-end by-hand check** — his to run, from the command line: `needle where`, then `needle start <a throwaway repo> card-x "reply READY then stop"`, `needle window <short>`, close the window, `needle sessions` (still working), `needle stop <short>`. The build ran exactly this and cleaned up after itself; the gate is the owner repeating it.

**What this close leaves for the owner's read.** The move (behaviour 4) and the whole rescue walk are proven on the floor, not against a real limit wall; the first real wall on a lane is where that closes. The daemon-and-session scope adoption (ruling 8) reparents Claude Code's own daemons into `claude-daemon-<slot>.scope`; work-3f and work-4a agreed it does not touch the hook or the supervisor, and the owner's call stands if he would rather the daemons stay in 0.1's unit until slice 03 retires it. The suite is 154 backend tests with 26 ratchets, `tsc` clean, 13 vitest.
