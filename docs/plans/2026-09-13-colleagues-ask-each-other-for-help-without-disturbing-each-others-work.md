## Intent

A colleague should be able to ask another colleague for help and get an answer, and neither the asking nor the answering should disturb the other's work or what the board says about it. Today both halves fail. Asking is half impossible: a colleague running in a terminal the owner opened himself is refused by name, and the only other way to reach one needs a project and a card number, so a colleague working on no card has no address at all — which is why the coordination he ordered on card #83 with his own Codex thread never happened. And asking is damaging where it works: every time a colleague is woken to read someone else's work, the board reads it as work on the card whose copy of the code it happens to be sitting in, and a card the owner was told was finished is reported as under way again with nobody on it. When this is done, a colleague can hand a note to any colleague on the machine, on a card or not, of either kind; the note waits for that colleague's next word rather than interrupting it; and nothing about the helper's own card moves because it helped.

The rejected alternative, and why: giving an idle colleague a turn of its own — typing the note into its terminal so it answers now. It is what makes waiting on an answer worth anything, and it was this plan's first shape. Rejected on 2026-09-13 on the owner's answer above: the terminal is his, a note typed into it while he is typing is exactly the disruption this plan is named after, and a race between two typists is not something a check can hold. The note waits instead, and item 5 makes a note nobody picked up visible rather than lost, which is the honest cost of the choice.

## Proof of search

Named before this plan proposes anything new; the presumption was that each piece already exists, and almost all of it does.

The note itself exists: the machine's watercooler is a directory of note files that colleagues of either kind already talk through, read by the board and never written by it (`runtime/discussion.py`, `domain/watercooler.py::Note`). It is reused, not rebuilt, and the project's own watercooler stays the project's — the two stay two, which is plan 17's ruling 3.

The record exists: `domain/call.py::Call` is already the row a wait stands on and the loop tends, with one reading shared by both (`runtime/calls.py::judge`). A note is that row with a different delivery, not a second kind of row.

The delivery exists: `board/word.py::notes_word` already turns a note on the machine's watercooler into a sentence in a colleague's own context, `hooks/needle_hook.py::word` already carries it in on the colleague's next act without ending a turn, and `api/loops.py::_party_to` already makes a colleague party to the note of a call it was called with, by its session id. The one thing missing is the address: `/api/word` is keyed by working directory to a project and a card (`api/loops.py::Loops.word`, `api/app.py`'s word route), so a colleague that is not working on a card is unreachable however many notes are written for it. That is the first new thing.

The refusal exists: `runtime/launch.py::call` already refuses to resume a colleague in a terminal of its own and already refuses one mid-turn, and its own words already point at a note as the other half. The note form belongs beside that refusal, not in a second verb of its own.

The board's true source exists: `domain/session.py::SessionSlot` already records the card a colleague was started on, written only by the thing that started or moved it. `infrastructure/store.py::record_session_slot` overwrites that field when the same colleague is called elsewhere, and the three readers that get a card's colleague wrong — `board/lane.py::lane_for` (the winner among the rows in the card's copy of the code), `board/lane.py::should_enter_executing`, `board/lane.py::close_is_current` under `where_a_card_goes` — all read the directory or a clock instead. Nothing new: one field kept beside the one that is overwritten, and three readers pointed at it.

What exists nowhere, and is this plan's to build: an address for a colleague that is not working on a card, and any statement anywhere of whether a note was picked up.

## Terrain

`runtime/launch.py` (the call and its two refusals, where the note form goes), `runtime/service.py` (the typed way in, and the refusal for a colleague on another machine that stays as it is), `api/board_cli.py` (the verb, beside `watercooler` and the rest), `api/loops.py` and `api/app.py` (the word channel and its second address), `board/word.py` (the sentences a note becomes), `runtime/discussion.py` (the notes read), `domain/call.py` and `domain/session.py` (the two records), `infrastructure/store.py` (the record that is overwritten, and the change to the board's memory that stops it), `board/lane.py` (the three readers), `runtime/codex.py` (what can and cannot be reached of the other kind), `tests/board/test_lane.py`, `tests/runtime/test_calls.py`, `tests/api/`, and new checks under `tests/ratchets/`.

This plan changes the board's own memory (item 1), so its work runs against a private copy and the shared board is only read; it also changes what every running colleague hears, so it lands when no other work has hands on any project.

## Items

1. **A colleague is remembered by the card it was started on, whatever it is asked to help with later.** The record the runtime writes when it starts a colleague keeps that card as a fact of its own, and a warm call writes what the call needs beside it rather than over it. Records written before this read as they do today and are never guessed at.
   *Done means:* a colleague started on one card and then called to help on another still reads, in the record and on the board, as the first card's; the close's check of who read the work independently gives the same answer before and after that call, where today it can give a different one; a colleague nobody started on a card names none rather than naming the last thing it was called for.
Hands out: search — every place that reads the card field of that record, with path and line, so items 2 and 3 correct all of them and none is left reading the old meaning; verifies by opening each hit and confirming it is a read of that field and not of a card number from somewhere else.

2. **A card's colleague is the one it started, not whoever is sitting in its copy of the code.** The card names its colleague from item 1's record first, and falls back to the directory only when the record says nothing. A visiting reader is reported as a visitor, in its own words.
   *Done means:* a card whose own colleague is alive while a reader of the other kind ended in the same directory reads as working, never as died, and offers no resume for a row the runtime cannot resume; a card with only a visiting reader in its directory says a reader is there and does not claim it as its own work or its own death; the card the visitor was started on is the card that still speaks for it.

3. **A finished card stays finished when its old colleague is asked for help.** Both the entry and the exit take the correction, because today they are wrong in opposite directions. A colleague sitting in a card's copy of the code that was started for a different card never moves that card into Executing; and the check that asks whether a close belongs to the work in front of it stops measuring against an entry that should never have happened.
   *Done means:* on a test board, a closed card whose old colleague is woken to read another card's work stays exactly where its close put it, with nothing added to its history; the same card genuinely restarted on its own work enters as it does today; a card wrongly opened before this lands returns to where its close put it on the next read with nobody touching it, and never to the column that asks the owner to decide something that is already done.
Hands out: execution — running the entry and exit readers against a test board in the four states (closed card with a visiting colleague, closed card restarted on its own work, card wrongly opened before the fix, card genuinely under way) and reporting each answer verbatim; verifies by reading the reported column and history against the test board's own rows.

4. **Any colleague running on this machine can be handed a note, on a card or not.** A note addressed to a live colleague by the name the one list already shows, of either kind, working on a card or not, is accepted and recorded as the same row a call is, so waiting on the answer reads it and the loop tends it and ends it. Nothing is resumed and nothing is stopped: the two refusals that stand today stay standing, and the note is what they have been pointing at.
   *Done means:* from any session, a note to a colleague running in a terminal the owner opened himself is accepted where a call is refused, and the caller can wait on it; a note to a colleague working on no card is accepted and reaches it; a colleague that cannot be reached at all — one on another machine, one of the other kind with no way in — is refused at the door in one sentence naming which, with no row written and nothing half-sent; and no note ever ends a turn or a process.

5. **The note arrives as the colleague's next word, and a note nobody picked up is visible rather than lost.** A colleague at work reads the note on its next act, the way it already hears the board; a colleague idle at its prompt reads it when it next takes one. Because the second may be a long time, a note that has been handed over and not yet picked up says so where both the owner and the colleague who sent it can see it.
   *Done means:* a colleague mid-turn picks up the note with no turn ended and nothing else about it changed; a colleague idle picks it up on its next word; a note standing unpicked is shown with who sent it, to whom and when, and the caller's wait says it is handed over and not yet read rather than answering with silence; a note picked up stops being shown as standing without anyone saying so.

6. **A check refuses each shape that caused this.** Two checks, at the altitude of the intent and not of today's method: a card's colleague may not be chosen by the directory alone while the record names one, and the note path may not resume or stop a colleague.
   *Done means:* the first fails when the readers are fed a directory with a visitor in it and a record that says otherwise, and passes when they read the record; the second fails if the note path is made to resume; each names in its own words the defect it holds and the date it was found, so a later session reads why it is there rather than deleting it as ceremony.

## Acceptance

- A colleague asks any other colleague on this machine for help and gets an answer back, and nothing on the board about the helper's own card moved because it helped.
- A card the owner has seen finished is never reported as under way again because someone asked its old colleague for help, and a card wrongly opened that way rights itself.
- A note handed to a colleague that is busy elsewhere is either picked up or visibly waiting; it is never silently lost, and the owner is never the one carrying a question between two colleagues.
- The colleague in the owner's own terminal is never typed into, interrupted, or resumed beside itself.
