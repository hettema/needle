# 02 — The runtime

**Status:** PENDING
**Written:** 2026-09-04, the morning after slice 01 landed, from `docs/INTENT.md` lesson 1 and the runtime half of Needle 0.1 as read on 2026-09-03 (nine fixes in one day, all here).
**Effort gate:** xhigh — this is the half of 0.1 that failed, and it failed on facts that no type carries: one session registry per subscription, a browser opener that strips its environment, a launcher whose child is the terminal, a daemon that forks a session on resume. **Sequencing:** after 01. Slice 03 (the doors and the loops) is the board's use of what this slice provides; nothing in 03 starts until the runtime's four jobs are proven from the command line.

## Intent

The board reads what runs. It never is the thing that runs. This slice builds the thing that runs as its own service with four jobs, each usable from the command line and from the owner's own terminals before the board ever calls it:

1. Know every session on this machine as one list, whatever subscription it runs under.
2. Say where work runs next: the strongest model on any subscription that still has it, the next model only when the top one is exhausted everywhere.
3. Start a session where the rule says, in its own worktree and its own process scope, so nothing the board does can end it.
4. Open a window into any session, prove it opened, and let the owner close it without ending the session.

When this slice is done, 0.1's launcher, rescue, window code and ladder are all replaceable by calls to this service, and the owner's own terminal gets the same model rule as a lane.

### 1. One list of sessions

Claude Code keeps a session registry per config directory (verified 2026-09-03: `claude agents --json` under one subscription cannot see sessions started under another). 0.1 polled only the registries its ledger remembered, and forgot one on the owner's answer, so a live lane rendered as a stopped copy of itself. The same session id also appears in several registries after a cross-subscription resume, and only one copy has a process.

Done means: the runtime lists every session across every declared subscription slot as one typed list, each row carrying its slot, its short id, its session id, its working directory, its state and whether a process exists (`/proc`, never the registry's word alone); when one session id appears in several registries, the row with a live process wins and the stale copies are named as such; a session with no process is never reported as working. The list is what the owner's terminal, the board and every other caller read.

### 2. One model rule

The owner's ruling (2026-09-03): use Fable 5.1 whenever we can; only when Fable 5.1 is exhausted on all my subscriptions do we switch to Opus. 0.1 encoded this correctly in one function and wrongly in a second one that the page rendered, so the card said Opus while Start ran Fable. 0.1's conversation doors never asked either function and died on the first limit.

Done means: one function answers "where does work run next" for a given starting slot and a set of rungs already tried, from the per-slot allowance cache (`~/.cache/omarchy/claude-acct/<slot>.json`, refreshed by `claude-acct`) and from the CLI's own limit messages; every caller, including the owner's terminal through a `needle claude` wrapper, gets the same answer; the answer names the slot and the model, and a slot whose signed-in identity is not the one it is supposed to hold is never chosen (the identity check the statusline already does, `oauthAccount.emailAddress` against `accounts.json`).

### 3. A session starts where the rule says, and nothing the board does can end it

0.1 spawned lanes from its own process, so they landed in its service cgroup and died with every restart. It resumed sessions to move them, which forks the session id and, when the daemon still held the original, produced two copies of one conversation in one worktree (verified twice on 2026-09-03; `claude stop` first is what prevents it). A resume also loads the whole transcript, and a 10 MB transcript stuck on "loading conversations" for good.

Done means: a start runs `claude --bg` in a transient scope of its own (`systemd-run --user --scope`, one unit per session, named after the card), under the slot's config directory, with the prompt-settling flags a windowless session needs; a start is verified by positive evidence (a registered row that stays alive through a short window, a `StopFailure` read as death with its reason) and never by the launcher's exit code; a move to another slot stops the session first, then resumes it, and prefers a fresh session with the brief over resuming a transcript above a size the executing session measures; the runtime records the slot each session runs on in its own store, and clearing a session's rescue history never clears its slot.

### 4. A window into any session, closable without ending it

0.1 opened a window by running the launcher through a 30-second wait and killing the child when the wait expired; the child was the terminal. It also offered a "resume in a terminal" door on cards whose session was live elsewhere, which forked the conversation into a window the owner could not close without ending it.

Done means: a window is opened detached (no pipe, no wait, its own session) and proved by one more window under its app-id than before, within a deadline, or fails loudly by name; a window into a live session is always `claude attach`, so closing it ends only the viewer; a session live nowhere gets a fresh session in its worktree with the transcript as context, and the window's first line says so; app-ids follow the `org.omarchy.<kind>-<card>` contract so the compositor's rules place them, and every board window is a tab in one group on the owner's terminal workspace (the rule landed 2026-09-03); the runtime never opens a second window for a session that has one, and never reopens one the owner closed.

## What this slice does not do

It does not decide which windows should exist, when a lane is rescued, or what a card says about any of it. Those are the board's decisions and belong to slice 03. This slice provides the four jobs as a service and a command line and proves each one by hand.

## Terrain

- **0.1's runtime, as the record of what goes wrong.** In the Hello Revenue repository, `scripts/needle_board_server.py`: `_start_session` and `_next_rung` (the ladder, correct), `_work_model` (the second chooser, wrong), `_resume_lane` (the stop-then-resume and the ledger clear), `_open_terminal`, `_window_count`, `_ensure_lane_windows` and the window ledger, `_refuse_open_lane`; `scripts/needle_board_live.py::read_agents` and the lane merge; `scripts/needle_board_runout.py` (per-slot run-out knowledge, the lane ledger); `scripts/needle_board_accounts.py` (slots, cached allowances, `env_for`). Read as scenarios, with `tests/scripts/test_needle_board*.py` beside them. Nothing is ported.
- **The machine's facts, each verified 2026-09-03:** registries at `~/.claude/jobs/<short>/state.json` and `~/.claude-accounts/<slot>/jobs/`; daemons under `/tmp/cc-daemon-<uid>/<daemon>/pty/<short>.sock`; `claude attach` adds no registry row and exits when the session ends; the browser opener spawned by a login carries none of the session's variables, so `~/.local/bin/chromium-router` reads them from the process tree; a session's transcript lives under `<config dir>/projects/<cwd slug>/<session id>.jsonl` and a cross-slot resume copies it.
- **Subscriptions:** `~/.claude-accounts/accounts.json` (slot → Chromium profile → expected identity), `claude-acct` (login, cache, identity), the statusline's identity check in `~/.claude/statusline/statusline.py`.
- **The compositor:** Hyprland with a Lua config; `hyprctl clients -j` proves windows; `hyprctl eval` runs Lua at runtime; the board-terminal rule and group in `~/.config/hypr/hyprland.lua`; `omarchy-launch-tui --app-id=… <cmd>` opens a terminal whose process chain ends in `foot` itself.
- **Shape:** `runtime/` beside `board/`, reached through a typed interface the board imports and a `needle` subcommand family (`needle sessions`, `needle where`, `needle start`, `needle window`); the ratchet from slice 01 that refuses processes under `board/` stays the boundary.

## Acceptance criteria (behaviours)

1. `needle sessions` lists sessions from at least two slots as one list, with the live copy of a duplicated session id winning and the stale copy marked.
2. `needle where --from <slot>` returns the slot and model the ruling implies, given the cached allowances; with Fable spent on the starting slot and headroom elsewhere it answers Fable on the other slot; with Fable spent everywhere it answers Opus on the starting slot; a slot with the wrong identity is skipped and named.
3. `needle start <repo> <card> "<brief>"` starts a session in its own scope under the chosen slot, and `systemctl --user` shows the scope; stopping the runtime service leaves the session running.
4. A move to another slot leaves exactly one live copy of the session and records its slot; the record survives a runtime restart.
5. `needle window <short>` opens a tab on the terminal workspace, proven by window count, still open after two minutes; closing it leaves the session working; a second call opens nothing and says why.
6. No test opens a real window or touches a real subscription: the fixture floor from 0.1 (launcher made unfindable, slot root redirected) is rebuilt as ratchets here.
7. By hand at the close: the owner starts one session through `needle start`, watches it through `needle window`, closes the window, and confirms the session still working; the result goes in the plan's close-out.
