## Intent

Turning auto-fix on while looking at Hello Revenue fixes Hello Revenue's defects and nothing else. Today the auto-fix setting is one switch for every project: turned on from any page, the board takes the oldest verified defect from any board — Needle's own last, and only when no work is under way anywhere — so the owner cannot spend the machine on one board's defects without spending it on all of them, and on a laptop the board itself reports as full that is the difference between finishing one board's defects and killing work on three. After this plan the switch is one per project and the number of fix lanes stays one for the machine: the beat reads only the boards whose switch is on, the number caps what runs across all of them, the head on each page shows that page's own switch and names in one quiet phrase which other boards are on, and `needle dial` prints every board's switch. Which board's defects fix themselves is his ruling, board by board; how many the machine holds stays the machine's, one number.

What does not change: what the mark means, who verifies it, the order among the defects auto-fix may take (oldest first today; gravest first when #100 lands), the memory floor, and the rule that Needle's own defects wait for a quiet machine (#43).

## Rulings

1. **The switch is per board; the number is the machine's.** The owner, 2026-09-07 ("run it for the selected needle, not across needles") and 2026-09-12 ("if I auto fix HR it only fixes HR defects"). Plan 11's ruling that "the dial is one, for the board" is overturned for the switch and kept for the number: its reason — the limit is the machine's slots and its one trunk, not a project — was always about the number and never about which board's defects he wants fixed. Rejected: the carried suggestion's per-board number of lanes, because it re-decides the machine's ceiling once per board and then needs a second cap so the sum does not exceed the machine, which is two settings that mean one thing; a second machine's room enters through #83, not through a count per board.
2. **The order among boards that are on is the beat's, never the page's.** With two boards on, the beat takes from them in its one order (oldest first today; gravest first under #100). Rejected: "the board I am looking at first", because the page open in a browser is not a fact the beat can read, and he may have two open. Rejected: a rank of boards, because the switch already says which boards he wants drained, and a rank on top of it is a second way to say the same thing.
3. **A reading is never gated by the switch.** A reading enters nothing (#100's ruling 5); with any board on, readings run on every board as they do today, and #100's item 4 makes them run with every board off. This plan only rephrases the beat's early return and does not remove it, so the two plans do not fight over one line.
4. **Placed in Up next below #82 and #81, ahead of #100.** The owner, 2026-09-12: "put them in the right order in up next for me". #80 first because it is the smaller change, it is what lets him turn auto-fix on for one board at all, and #100's order slots in behind it as the order among the boards that are on; below the two cards he had already ranked there, because those are his ranking and this conversation applies it rather than reorders it.
