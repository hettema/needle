## Intent

A session that needs a colleague's judgment gets it the way a person walks to a desk: the colleague is called warm, with the thread and the question, answers in the record, and the caller can see them working and is told the moment the answer lands. Today the chair of a discussion launches a stranger, waits blind, and polls a terminal every thirty seconds; the stranger rebuilds the whole record before its first word; a running colleague who could have answered warm joins only if the owner happens to invite it; three of eight launch attempts failed at the harness before any model ran; and the board lists the one warm session of the morning as `idle` while it works. The doctrine already says sessions push and the board never polls (`docs/INTENT.md`, lesson 3) and that a running lane hears the board within a minute (plan 10). This plan brings a discussion under the same rule.

What does not change: the two watercoolers stay two — the machine's directory for sessions on this laptop, the project's in the store for lanes (plan 07, ruling 1) — and a reviewer or a discussant still speaks on the machine's; every colleague's lifecycle stays with its own lifecycle owner, reached through one Needle runtime call (`claude-acct` is today's first adapter, not the organisation's identity); the board reads and never writes into a repository or the discussion directory.

### 1. A colleague is called warm, one way
A caller names a running session (or a provider slot, for its most recent) and a note, and the runtime asks that colleague's lifecycle owner to resume the session with the note's path and the objective as the brief, answering with the session it woke or the one-line reason it could not. The first adapter is the by-hand Claude form that worked on 2026-09-05 (`printf '%s' "$PROMPT" | claude-acct use <slot> -r <id> -p …`); the refusal it produced first ("No deferred tool marker found in the resumed session … Provide a prompt") becomes the verb's own message, so a call whose brief did not arrive is refused, never started silent. Done means: the verb resumes a named session and that session's first request after the call carries the brief (its transcript shows it); a call with an empty brief, an unknown provider, or a session that cannot be resumed is refused with the reason and exit 1; `needle --help` lists the provider-neutral verb; a call never spawns a provider process of its own — the runtime's launch path and the provider's lifecycle owner remain the only path. Hands out: `search` — every place the runtime and `claude-acct` resume an existing session today (`runtime/launch.py`, `api/doors.py::resume` and `answer`, `claude-acct use -r`, `needle move`), so the verb extends the existing runtime boundary with a brief rather than creating a Claude-shaped second way; verifies by reading the one launch function and provider adapter the search names as the resumer.

The seam with the lifecycle owner, read from it rather than assumed: a called session is the shape the runtime already tends — a windowless session of the project's checkout, the shape a reading and a planning session have (plans 09 and 11) — never a one-shot and never a terminal's attach; the by-hand form above is the form's evidence, not its shape. Why: the owner hands off, recovers and lets the runtime move only what it can find again, and that is a session the runtime tends. For the first adapter a one-shot is, by the owner's own rule, "nothing to recover" on a transient death (`interrupted()`), its wall is invisible to the one list, and its state reads `idle` while it works — the baseline's fourth row. So across the owner's account handoff or transient recovery the call stays one call to one colleague: the runtime stops the old process before the new one exists, the call's record follows the forked session id as a reading's does, the brief is in the transcript the resume rebuilds and is re-supplied by the runtime's fresh-session brief when the transcript is above the resume limit, and a second wall inside an hour parks rather than thrashes — all as they stand, none re-implemented here. And a session whose process is alive is never resumed beside itself: one whose turn is done is stopped and resumed by the runtime as the Answer door does; one in a terminal of its own is refused with that reason, and the note reaches it as item 2's word. Done means, added: on the machine's wall fixture (`~/.claude-accounts/fixtures/fake429.py`, `wall` raised mid-call) a called session is moved once by the runtime, the same call's note lands from the session that lives, the one list shows one call and no second, and the caller is told the move in the runtime's words; a call to a session alive in a terminal is refused with the reason and no second process exists; a provider whose lifecycle owner cannot hand off or recover is refused or ended with that said, never silently retried by the verb.

### 2. A note landing wakes the waiter; nobody polls
A caller that has asked waits on one call that returns when the note it names lands or changes, or when a stated ceiling passes, instead of a terminal poll every thirty seconds; and a running Claude session that is party to a discussion hears a new note in the machine's directory the way a lane hears the project watercooler — inside its own session, within a minute, once (plan 10's word). Done means: on a fixture directory, the wait returns within a second of a note being written and returns with "nothing" at the ceiling; a session with hands on a worktree whose card names a discussion note sees the next note's path and first line as its next word and never sees its own; the chair of exchange 5 in the close-out shows zero polls in its rollout. Hands out: `search` — where the hook's word is assembled and read (`api/loops.py`, `board/lane.py`, `hooks/needle_hook.py`, `infrastructure/store.py`'s heard-mark), so a discussion note becomes one more sentence in the word and not a second delivery; verifies by reading the assembler the search names. And a wait never outlives the colleague it waits on: when the called session is blocked, moved or ended without its note, the wait returns at once with the runtime's own words for it (the wall's reason, the rescue's note, why it ended), so the caller reads the owner's truthful state instead of a ceiling — done means: on the fixture, a wait on a called session that ends without a note returns before the ceiling and says why.

## Acceptance criteria
1. A provider-neutral call to a named running session resumes it through that colleague's lifecycle owner with the brief in its first request; an unknown provider or a call whose brief cannot arrive is refused with the reason; no provider process is spawned outside the runtime's launch path. The called session is a session the runtime tends: on the wall fixture it is moved once, the same call's note lands from the session that lives, and the one list shows no second call; a session alive in a terminal is refused, not resumed beside itself.
2. A waiter returns within a second of the note landing and at the ceiling otherwise, and before the ceiling with the runtime's words when the called session is blocked, moved or ended without its note; a running lane party to a discussion hears a new note once, in its own session, within a minute, never its own.
3. `needle sessions` and the board show what a called session is doing and how long ago, and the cost per tool call is written beside plan 10's.
4. The review record holds six exchange rows with both parties' numbers, and the close-out names the outcome.

## Loop
We think calling a running colleague with the thread, telling the caller when the answer lands, and showing the colleague at work will change the time from ask to answer and the tokens spent per answer in a discussion, because the cost today is context reconstruction and blind waiting, not thinking: three cold replies re-read the same five sources, and the chair re-sent its whole context every thirty seconds to learn nothing. Fixed now: on the six exchanges, a warm reply lands in at most half the time of its cold pair, re-reads at most one source a prior note already cited, and is corrected by a later reader no more often than the cold ones; the chair of a warm exchange polls zero times. If all three hold, items 1–3 stay and the machine's watercooler is treated as delivered, not posted. If warm is faster but corrected more often, the speed was bought with grounding: the ruling becomes cold for a first grounding, warm for follow-ups in a thread, and item 1's brief says which. If warm is not faster, the cost is thinking and the card closes on item 3 alone — a colleague who takes ten minutes visibly is not a frustration, one who takes ten minutes silently is. If the chair still polls, item 2 did not reach the chair's seat (Codex is not a lane and hears no word), and the wait verb is the fix, filed as inside the change.

The ask's shape is the confound: exchange 3 was the narrowest question of the morning and the slowest reply, because the question needed two rollouts and a binary. So pairs are matched on the count of questions and the notes named, and the reader counts them before reading the times.

## Rulings
1. **One provider-neutral verb through each colleague's lifecycle owner, never a second launcher.** `claude-acct` is the first adapter because Claude is the first callable colleague, not because Needle is a Claude organisation. Rejected: a caller running `claude -p`, `claude --resume`, or another provider's process itself — that is the 08:37 launch, unsupervised, which the chair then had to kill; the machine's rule is that the lifecycle owner owns a session's life.
2. **Delivery through the word a lane already reads, not a second channel.** Rejected: a watcher process or a desktop notification per note — a third way to hear, and one that reaches the owner's screen instead of the session that asked. The chair's seat, which is not a lane, gets the wait verb instead.
3. **Two watercoolers stay two.** Rejected: moving the machine's discussion into the store — the directory is where sessions of any make write today, the entrance card makes Codex read it, and the store attributes a line to a card's lane, which a discussant is not (plan 07, ruling 1).
4. **The measure is written by both parties at the time, never reconstructed by one.** Rejected: one session deriving all six rows after the fact from the rollouts — the reader would be a party, and the baseline above was already written that way once; the six new rows are not.
5. **A call is a session the runtime tends, and the verb owns nothing of its life.** The invariant a call keeps across the owner's handoff or recovery — one call, one colleague, the brief kept, the caller told the truth — is held by shapes that exist (the runtime's stop-then-resume, the record following the forked id, the fresh-session brief, the parked second wall, the registry's blocked state), and the plan's only act is to choose the shape those hold for. Rejected: the verb classifying a death, choosing a slot, retrying a transient error or reassigning a call to another colleague — each is the lifecycle owner's, and a second copy of any of them is the drift the machine's ruling of 2026-09-04 (one rule, one detector, two executors) exists to stop. Rejected: a one-shot as the called shape — the form that worked once by hand, and the one the owner will not recover and the list cannot see. Rejected: a call that silently replaces a colleague whose provider cannot resume it — the refusal says so and the caller decides; substitution across providers is another card.
