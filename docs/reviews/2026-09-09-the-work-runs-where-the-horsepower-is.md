## Dispositions

1. [seam] **A group's owner was matched by pid alone across machines.** `board/dial.py::who_is_home` looked every group's pids up in one map of every session's pid, so a group read on the rented machine could read as home to a laptop session holding the same number and never be swept, or a stranger there be called a session here. FIXED: the map is keyed by `(machine, pid)`, both stamped by the runtime that read them; a floor case holds two groups with the same pid on two machines and reads the laptop's home and the rented one's nobody home.
2. [feature] **The Start preview never named the machine, while the plan's ruling said it does when the board knows more than one.** `board/lane.py::driver` built its words from the rung alone. FIXED: it appends `on <machine>` when the placement carries a name, which `api/loops.py::_placement` blanks on a one-machine board, so every existing face reads as before.
3. [seam] **A fresh session from a remote session's transcript is judged against the wrong transcript.** `runtime/windows.py::look_command` reads the transcript's size here (`machine.transcript_size`) for a session that ran on the other machine, finds nothing, and asks for a resume there rather than a fresh brief; the other machine's own `claude --resume` then holds the size rule. NO CHANGE: a resume that the other machine refuses for size is a window whose first line says so, loud and once, and the fresh-brief branch is a size optimisation, not a claim; noted for the live read of item 4.
4. [record] **The desktop's `needle tell` keeps its own ledger of how a popup was answered, beside the desktop's store, not beside the board's.** The loop writes that ledger's path and never reads it back (`api/loops.py::_tell_owner` writes `told.log`; no reader), so nothing the board shows depends on which machine holds the file. NO CHANGE; item 3's live read says which machine the plan's own reading of card #41 should read the ledger on.
