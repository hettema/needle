## Dispositions

1. **The scope adoption reported a real success as unverified.** `StartTransientUnit` returns a queued job, so the immediate `/proc` recheck raced the move; a live start read "running, but not in its own scope" while `systemctl` showed the scope holding the process. Bad information about the one thing that makes a lane un-killable — FIXED (ruling 7): `scope_session` polls `/proc` until the cgroup settles, bounded by `SCOPE_SETTLE_SECONDS`. Re-verified live: the next start read `scope needle-card-live-2.scope`.
2. **The teardown killed by bare pid — the caller-matching trap.** The floor's `kill_everything` SIGKILLed every recorded pid; a test that handed a session its own `os.getpid()` as a live pid then moved it made the fake `claude stop` kill the pytest process (exit 137). FIXED: teardown kills a pid only when it is still a `sleep` with the start time recorded for it; the two tests that used `os.getpid()` for a movable session were rewritten to exercise the stale and interactive guards without ever handing a real stop the runner's pid.
3. **A ResourceWarning from the detached launcher became an error under the suite's warnings-as-errors.** `machine.spawn` dropped the launcher's handle; its `Popen.__del__` warned the child was unreaped. FIXED: `spawn` waits briefly for the launcher, which exits at once by design (`exec setsid`), reaping it without holding the window it started.
4. **`windows.py` bound `RESUME_SIZE_LIMIT` at import**, so a test monkeypatching `launch`'s copy did not reach it and the size-limit banner never appeared. FIXED: the window module reads `launch.RESUME_SIZE_LIMIT` and `launch.fresh_brief` through the module, one source for the limit.

## What the build learned the plan got wrong

- The plan's item 4 said a start "prefers a fresh session with the brief over resuming a transcript above a size the executing session measures". Measured: the resume hang is an interactive-session fact, not a loader fact (print mode reads 14.6 MB in under two seconds). So the limit governs the interactive surfaces — a move's resume and a look window — and the number (8 MB) is a belief with a loud loop, since every resume is verified and a hang reads as unconfirmed. Written so in ruling 9.
- The plan named a `needle claude` wrapper for the owner's terminal. It was withdrawn when the model rule moved wholesale into `claude-acct` (`claude-acct use/auto` is already that wrapper); the plan text and rulings say so.

## Not done, stated

- **The daemon-and-session scope adoption reparents Claude Code's own daemons.** Agreed with `claude-acct` (work-3f, work-4a) that it does not touch the hook or supervisor, which key on env and pid; the owner's call stands if he would rather the daemons stay in 0.1's `needle-board.service` until slice 03 retires it.
- **The board does not yet call any of this.** Start, the machine moves, the doors and the loops are slice 03; this slice is the service and its command line, proven by hand.
- **The live-check commands live in the session's scratch directory**, not the tree; the plan's behaviour 7 is the repeatable form of them.
